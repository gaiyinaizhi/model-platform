# model-platform

供 `visionlab`、教学平台、机器人和无人机等独立产品复用的模型训练、评估、交付与推理服务运行工程。

**状态：2026-10-12 设计初稿，待实施。** 当前仓库只有基础文档与忽略规则，没有可运行服务、训练代码、已验证接口或设备适配。本文中的架构、流程和目录建议均为设计目标，不代表已经实现。

## 定位

把算法执行、训练记录、评估证据、模型交付和推理服务运行能力放进独立仓库，让不同产品共享模型能力，业务产品继续独立演进。

- **共享模型能力**：复用算法配方、数据版本引用、训练执行、模型评估、技术版本信息、交付产物和持续运行的模型 API
- **产品各自负责业务**：`visionlab` 是独立的专业视觉实验与训练工作台；教学平台定义教学接入、课程、任务与成绩；机器人产品负责机器人控制；无人机产品负责飞控与运行安全
- **明确资产管理边界**：实现与可复用能力待核实；已有能力优先复用，没有时只补最小资源引用与存储适配，不建设完整资产中心，也不因此阻塞首个切片
- **Python 承担算法执行核心**：先做模块化工程，再按实际负载决定是否拆分服务
- **Sluggard 是业务管理的优先待验证方案**：它与业务后端的具体分工、接口及复用程度尚未确认，不视为现成集成或已锁定依赖

## 本工程负责什么

1. 描述和执行可复用的 `AlgorithmRecipe`
2. 引用外部管理的 `DatasetVersion`，记录可追溯的训练输入
3. 管理 `TrainingRun` 及每次执行尝试，保留状态、日志和失败原因
4. 生成可复核的 `Evaluation` 和不可变技术清单，通过业务后端登记或关联 `ModelVersion`
5. 按 `TargetProfile` 准备 `DeploymentPackage`，向业务后端提供交付结果与发布回执
6. 以 `ModelService` 描述模型接口契约，以 `ServingDeployment` 记录实际部署和实例状态，承担后端推理服务的启停、健康就绪、更新及回滚

模型可以来自自训、导入、厂商或外部 API。不同来源的训练、评估、导出和部署能力均需单独声明与验证，不能假定每种来源都支持完整流程。

### 三种推理运行形态

- **后端持续 API**：由本工程的模型运行层加载经验证的产物并持续提供推理服务，管理实际实例、资源、endpoint 与健康就绪状态
- **端侧设备运行包**：交付适配目标设备的包，由设备侧运行；设备安装、控制和安全责任仍属于对应产品
- **外部厂商 endpoint**：适配有授权的远端接口，记录提供方、版本限制与调用状态，不把外部调用描述为本地部署

以上均为待实施的设计范围。模型 API 的预处理、推理、后处理及版本契约属于本工程；业务 API、成绩、告警规则等由 Sluggard 或相应业务产品负责。

## 不负责什么

- 课程编排、教学评分、学生成绩或产品业务任务审批
- 机器人运动控制、无人机飞控、安全决策或设备实时控制闭环
- 重建资产中心、通用业务后台或完整 MLOps 大平台
- 在未验证的设备上承诺兼容性、性能或安全可用性

训练通常在服务器或训练服务执行，端侧通常消费推理产物。模型转换或量化后仍需验证精度、运行时兼容性、延迟和内存等指标；目前未选定具体设备。

## 先打通一个真实流程

首个实现目标只覆盖一个选定任务：

`AlgorithmRecipe → DatasetVersion 引用 → TrainingRun → Evaluation → ModelVersion → TargetProfile 对应的交付产物`

选择一种可用数据、一种训练执行方式和一个明确的推理输出目标，真实完成训练、评估及产物验证，再以该真实交付包验证首个 CPU 或服务器持续推理服务，随后分别接入 `visionlab`、教学平台和无人机设备。纯 mock 可以先验证契约和状态流转，但不计作真实训练、服务就绪或设备验收。训练完成、生成交付包与服务 ready 是三个不同验收结果。

## 业务管理与执行边界

业务任务在 Sluggard 或业务后端管理，本工程保存执行事实。双方以业务任务 ID、执行 ID 和幂等键关联，业务界面展示的执行状态是投影，不另建一套独立修改的状态真相。

推荐由 Sluggard 或业务后端维护业务权限、权威模型登记、部署期望及发布审批；本工程提供不可变技术清单、执行与评估事实，并主写实际实例的 ready、健康与运行观察状态，通过稳定 ID 和幂等过程关联。期望状态与观察状态分别记录，业务界面展示运行事实的只读投影，不双写实际状态。资产管理边界的实现与可复用能力待核实，见[架构设计](docs/architecture.md#模型登记与技术清单的单一主写边界)。具体归属、API 和字段须在核实后评审，不在本次初始化中假定存在。

## 开始贡献

先读三份基础文档，区分已实现内容与设计目标。以小且可验收的变更推进；新增接口、引入基础设施或改变跨系统数据归属前，先确认边界与契约。

不要向 Git 提交训练数据、模型权重、运行产物、密钥或凭据。产物应保存在受控存储中，由仓库中的代码与元数据约定引用；`.gitignore` 不能替代提交前检查。
