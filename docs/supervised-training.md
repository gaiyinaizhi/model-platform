# 受监督训练执行（阶段 1）

本增量把静态白名单配方的训练、导出及随训练评估移到受监督子进程，父 Worker 保留队列、日志、失败终态及模型登记的写入权。目标是为可确认停止建立执行边界，不是已经实现运行中取消。

API、run/attempt 状态、数据库 schema、排队撤销、显式失败重试与三次上限不变。独立评估和 serving 保持原协议。不新增依赖，不迁移现有数据库，不改写历史代码指纹。

## 平台与进程所有权

训练 Worker 现在明确要求 Linux 的 `prctl(PR_SET_PDEATHSIG, SIGKILL)`。启动先运行隔离预检；平台或内核机制不可用时在领取、恢复任务前拒绝启动，不回退到不受监督执行。直接调用内部 execute 也必须取得 Worker 租约，不能绕过已有执行者。

父 Worker 持有排他的 worker 文件锁，向实际启动的训练子进程继承同一 open-file-description。此租约只 close，不显式 LOCK_UN；因此父进程死亡后，只要旧子进程仍持有描述符，新 Worker 就不能取得锁、执行恢复或领取任务。这也保护解释器尚未安装父死信号的启动空档，以及被 SIGSTOP 暂停的子进程。所有锁持有者结束后才释放租约；不会根据数据库旧 PID 杀任意进程。

子进程在项目或算法代码导入前安装内核父死 SIGKILL，并复核实际父进程身份，覆盖安装前父进程已经退出的竞争。它只继承请求、结果通道与租约所需的描述符，随后关闭这些描述符的可继承标志。独立解释器禁用字节码写入，并使用全新空的 pycache prefix，防止读到旧项目缓存字节码。

父进程只通过自己创建的 Popen 对象处理终止及 wait。正常返回、异常、协议拒绝、超时均在确认子进程退出并回收后，才进行登记、记录失败或继续领取。父进程突然退出时，旧 attempt 保持 running，后继 Worker 取得租约后仍按既有 interrupted/failed 规则恢复，不自动重训。暂停在安装父死信号前的子进程可能持续持锁：这是安全地阻止恢复，不是伪称它已停止。

当前支持的静态训练实现使用线程，不提供任意子孙进程树治理；新增会启动其他进程的配方必须另行审查。子进程分离不是 OS 安全沙箱，不提供独立用户、cgroup、硬 CPU/RSS 配额或生产多租户安全保证。既有独立评估子进程并未获得本轮训练租约改造，不扩大其恢复保证。

## 数据、日志与结果边界

父进程把已验证的请求、不可变数据绑定、提交和已加载环境通过受限临时文件交给子进程。子进程不实例化 Store、不领取任务、不登记模型；数据集元数据使用只读 SQLite 连接核验，训练产物仍写入当前 attempt 的既定路径。

结果使用单独的文件描述符传输严格 JSON 换行帧，不混用 stdout。子进程 stdout/stderr 丢弃，避免外部库输出挤占协议或暴露原始异常。当前预算为输入 4 MiB、单结果帧 1 MiB、整个结果流 2 MiB、最多 256 条日志、单条日志 4 KiB。重复字段、非有限值、错误顺序、截断帧、无终态结果、超限及非零退出均拒绝。

日志仅允许已有配方的事件、字段和格式；计数字段必须为有界整数，指标必须是有限数值，hash 和技术 ID 有固定形状。未知异常仅转为固定错误码。结果限于受信任的内置配方，不开放用户上传可执行代码；结果字节预算和来源检查不能被解释成不可信代码沙箱。

子进程独立读取当前代码与环境，必须匹配父进程加载时和提交时的代码指纹；执行后再次核对。父进程检查来源、实际产物大小/hash，重新核对源码，并在原子登记事务中检查 attempt 仍持有发布权。旧 queued 记录遇到源码升级仍可能 execution_code_changed；不为让旧任务执行而修改历史。登记事务已经提交后，附加日志失败不会反向制造 failed 终态或失败日志。

## 时间预算与恢复

外层绝对单调时钟预算为原配方 training_seconds、export_seconds、evaluation_seconds 之和，再加 30 秒启动余量。既有配方各阶段仍使用原协作式检查；外层监督可在 native 调用期间终止子进程。父进程在结果收取、等待退出及登记事务关键位置核对截止时间，超时不发布模型。

这不是实时操作系统保证：父进程本身暂停、内核 I/O/调度阻塞可能延迟处理；确认退出前不得释放租约并谎报完成。无法及时退出的执行会阻止后继工作，而不是允许两个执行者重叠。未登记的部分产物不构成可服务模型，本增量不删除历史或实现 checkpoint 恢复。

## 验证与产品衔接

专项进程测试与完整回归、真实合成数据 CPU→ONNX 验收记录见 [supervised-training-verification.md](supervised-training-verification.md)。合成训练只验证工程执行和血缘，不代表业务识别质量、质量门槛或生产许可。

本阶段为后端独立增量，vision-lab 产品的后端源码锁仍指向已发布版本。批准发布后需用真实提交更新精确源码锁，并重新执行 launcher 回归；不能将尚不存在的提交写入产品锁，也不能跳过 launcher 摘要预检。
