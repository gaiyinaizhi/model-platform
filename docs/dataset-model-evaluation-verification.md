# 数据集训练模型独立评估验证

状态：2026-10-22，开发增量及独立审查通过，尚未提交或发布。准确边界见[契约](dataset-model-evaluation.md)。验证只使用自产数据，不使用用户文件或私有预训练权重。

## 实际 CPU / ONNX 验收

- 新生成两类数据，CPU 从零训练一轮，参数确实变化，注册 3,664,527 字节 ONNX。训练快照含 8 train、2 val、2 test；另一份预先冻结并发布的 evaluation-purpose 快照含 6 val、10 个真值框和 1 张负样本。
- 实际受监督评估的 AP50、AP50:95、AR@100 均为 0；TP=0、FP=0、FN=10，precision=null、recall=0。这是实际低质量小模型结果，不是回退值，也不是质量合格声明。
- 无应用模块导入的独立参考实现重新加载真实 ONNX，独立预处理、解码、过滤、NMS，并用直接 pycocotools 与贪心匹配重算。全部逐类/聚合指标、计数和规范化预测摘要一致。另有 11 项参考自检覆盖非零指标、无 GT、零预测、阈值/NMS 边界、排序/截断和坐标还原；受监督固定 ONNX 夹具给出非零 AP/AR=0.5。
- 28 项实际验收检查通过：同键重放无重复、归属/类顺序/摘要拒绝、接收后完整性失败不留部分结果、已识别 Worker 死亡后直接子进程终止和 evaluation_interrupted 恢复，不自动重试。
- 原模型 manifest、原训练 val/test 结果以及训练数据逐字节不变。25 个训练和 13 个评估归档成员与预先冻结字节一致，两份自产数据的解码像素摘要无交集。这只是本次夹具检查，不构成产品自动查重或统计独立留出认证。

## 官方云浏览器

Chrome 实测显式提交、轮询、历史/详情、失败记录、刷新恢复、0 与 null 的区别，以及报告/比较/错误图预览不可用提示。代理只对一次已接收 POST 丢失响应；刷新和离开再返回均未自动重投。修复并复测了未确认提示在重载后消失的问题，提示现在来自持久化未确认意图，不会被已完成历史记录替代。

显式“核对原提交”复用同键，返回原评估 ID。三个接收 POST 对应两个显式意图、两个唯一评估；只读 SQLite 核对总记录仍为 6，恢复结果只有 1 行，训练/模型/服务等 9 张表摘要不变。自建 API、Worker、BFF、Vite 和代理均已停止。捕获的 28 条浏览器扩展元数据错误单独披露，未捕获应用源错误。
